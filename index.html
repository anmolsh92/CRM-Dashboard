How access works

Anyone who signs up joins as a user. The bootstrap address becomes an admin on first sign-up.

Nobody gets in by signing up. A new account is created inactive and sees nothing until an administrator approves its invite request, choosing user or admin at that moment. The bootstrap address is the one exception, so the workspace can be set up in the first place.

Users read every record but may change only those where they are the seller POC. Admins change anything. No one can alter their own role or block their own account, so the last admin cannot be locked out.

Blocking works in two layers. Supabase Auth refuses to issue a token for a blocked address, so sign-in fails outright; and every row-level security policy additionally requires an unblocked account, which closes the gap where a token issued moments earlier would still be valid. A user blocked while signed in is signed out on their next page load. The bootstrap admin address cannot be blocked.
